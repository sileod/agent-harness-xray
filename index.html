Research & Data Methodology

How this data was harvested, compiled, and calculated.

🔬 Data Acquisition Strategies

Because different AI agents use different software licenses and deployment mechanisms, we employed a hybrid acquisition strategy:

  • Open-Source Codebase Analysis: For agents like Gemini CLI, OpenCode, and Aider, we directly parsed the repository source code to locate internal prompt assembly mechanisms (e.g., packages/core/src/core/prompts.ts for Gemini, and aider/coders/editblock_prompts.py for Aider).
  • Model Introspection & Extraction: For proprietary IDEs like Cursor and Windsurf (Cascade), we leveraged community prompt engineering directories (such as x1xhlol/system-prompts-and-models-of-ai-tools) that isolated active system instructions by triggering conversational debug gates or analyzing local Model Context Protocol (MCP) data streams.
  • Reverse Engineering via Source Maps: For Claude Code, we drew from the widely studied npm package source map leak incident of March 2026, which exposed the complete TypeScript codebase, including all 110+ system prompt segments, anti-distillation parameters, and internal tool rules.

📊 Token Calculation Standards

Since prompt formats differ, we normalized all estimates to ensure clean comparative baselines:

  • Tokenizer Baseline: All token weights are computed using the cl100k_base and o200k_base tokenizers, which power major frontier models from Anthropic and OpenAI.
  • Dynamic Additions (Turn 1 Context): Base calculations represent a clean checkout environment (excluding massive diagnostic traces or custom user codebases) to model the raw "harness tax" of the active agent wrapper.
  • Skills Context Tax: In Gemini CLI, the extensible skills system loads the name and description of all discovered skills on startup, creating a static overhead of ~5,000 tokens before any specific skill-action is activated.
